# 启动器基础交互

按用户要求，先提交既有样式，再实现上下选择、全局快捷键显示 / 隐藏、失焦隐藏及任务栏隐藏。原有样式基线提交为 `2a879d3`。

结果选择使用一个 selected-index 状态。上下键在首尾停止，不循环；滚动位置根据 54 像素行高和 162 像素可视区调整。鼠标点击结果更新选择并把焦点还给输入框。搜索和启动应用依然使用示例数据，不在此轮实现。

程序在主线程注册全局快捷键并运行 Slint 的持续事件循环，最后一个窗口隐藏不会导致程序退出。默认尝试 Alt+Space，系统提示已注册时尝试 Ctrl+Alt+Space。本机验证前者已占用，后者注册成功。FLOW_HOTKEY 支持明确覆盖；界面始终显示实际注册的组合。只响应首次按下，松开重置，避免长按导致反复切换。

显示窗口后等待原生尺寸就绪，重新居中并请求原生焦点，然后聚焦搜索输入框。Esc 和关闭操作执行隐藏；Ctrl+Shift+Q 退出程序。失焦事件安排一次延迟焦点复查，以避免旧窗口的异步失焦误隐藏刚唤回的新窗口。可见期间额外运行 80ms 的原生焦点检查，覆盖 Windows 快速重建窗口时未送达的失焦事件；隐藏后停止检查。

Windows 通过 winit 的 with_skip_taskbar 配置每次创建的原生窗口；可执行文件使用 Windows 子系统避免额外控制台。macOS 在事件循环构建时使用 Accessory 激活策略。macOS 实机验证待完成。

验证：原生窗口交互检查覆盖选择边界、选中项可见性、Esc、隐藏时循环存活、重复显示隐藏、搜索文字保留、第二个原生窗口抢占焦点后的自动隐藏，以及失焦后再次唤回。Windows 使用本测试进程内的 WM_HOTKEY 消息验证全局热键处理链路，不向其他应用发送输入。

重复启动修复：在构建图形后端和注册快捷键之前取得 OS 单实例锁。第二个实例通过本地 IPC 通知第一个实例显示窗口，然后以成功状态退出。锁与 IPC 保持到主进程结束；Unix 下只有锁持有者可清理崩溃残留的 socket 文件，避免并发启动互相删除活动端点。Windows 下第二个实例授权第一个实例获取前台焦点。启动错误显示独立错误窗口，解决 Windows 无控制台情况下错误原因不可见的问题。

实测启动主实例后再次执行 cargo run：次进程退出码为 0，主实例收到唤回消息，运行中的主程序仍只有一个。
